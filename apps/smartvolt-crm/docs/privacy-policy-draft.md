### 我們處理的資料及用途

當你聯絡已接駁的 WhatsApp 商業號碼，或作為公司成員使用 CRM 時，服務會按以下用途處理資料：

| 資料 | 用途 |
| --- | --- |
| WhatsApp 電話號碼（如平台提供）、平台識別碼（例如 BSUID）、個人檔案名稱 | 識別同一對話的聯絡人，將查詢交予所屬公司處理；沒有電話時不會虛構電話號碼 |
| 訊息內容、回覆及引用關係、訊息時間和識別碼、客服備註及處理狀態 | 顯示查詢、人工回覆、跟進及保留服務紀錄 |
| 已接受、已傳送、已送達、已讀或失敗等平台狀態與錯誤資料 | 顯示實際傳送結果、處理重複事件及排查發送問題；平台接受不等於已送達 |
| Meta 隨訊息提供的來源／廣告 referral 資料及其他事件欄位 | 識別查詢來源、維持訊息處理及核對紀錄；收到查詢不會自動登記為行銷同意 |
| 公司成員登入電郵、名稱、角色、公司識別資料、必要登入 cookie 及操作紀錄 | 登入、維持工作階段、限制公司存取權限及記錄操作責任 |

服務會保存經驗證的原始平台事件作為私有核對紀錄，其內容可能比收件匣顯示的資料更完整，包括媒體識別碼／中繼資料，以及平台隨訊息傳來的聯絡人、位置或其他欄位。目前收件匣只對未支援媒體顯示種類或文字提示，未實作媒體檔案下載、預覽及附件回覆。

目前接駁不會匯入私人 WhatsApp 的歷史對話；只會處理商業號碼接駁後平台交付的事件及透過本服務進行的操作。目前未啟用真實 AI 自動回覆、廣播或批量行銷發送。若日後改變處理用途，須先更新適用政策及安排所需通知或選擇。

### 誰可接觸資料

資料按公司工作空間分隔。獲授權公司成員可按角色查閱或操作其公司的服務資料；連接設定由公司 Owner 管理。一般收件匣不提供原始平台事件或已保存的供應商密鑰。受授權的系統維運及基建供應商可能因提供或維護服務而處理相關資料。

| 服務供應商 | 處理環節 |
| --- | --- |
| Meta／WhatsApp | 商業訊息傳遞、平台識別及狀態事件；亦按其適用條款及私隱政策處理資料 |
| Supabase | 公司登入驗證、資料庫及服務紀錄儲存 |
| Vercel | 網站及伺服器執行，處理網站請求、平台回呼及訊息發送請求 |

**[發佈前補充：各供應商適用的資料處理安排、實際儲存／處理地區及跨境處理說明。]** 這些服務供應商的具體法律角色須按實際合約及用途核實。

### 保安、保存及資料申請

正式部署的服務以 HTTPS 傳送資料，並以公司存取控制限制讀寫。WhatsApp App Secret 及 Access Token 由伺服器以 AES-GCM 加密保存；這不代表 CRM 內的訊息或原始事件具備端對端加密。

**保存安排：[Owner 須確認訊息、聯絡人、原始事件、操作紀錄及備份各自的保留期限、刪除或去識別化方式，以及需要保留的具體理由後填寫。]** 現時未有自動到期清除流程；部分原始事件及操作紀錄採用不可改寫設計，日常操作不能直接更改或刪除。不能把此設計解讀為已決定永久保留所有個人資料。

你可透過上述私隱聯絡渠道申請查閱、更正或刪除與你有關的資料，並說明相關聯絡方式及資料範圍。我們會先合理核實申請人的身分，再說明可採取的處理、需要補充的資料及任何必須保留的理由。目前未提供自助刪除功能；本草稿不設定未經核實的完成時限。不要在申請中傳送密碼、供應商密鑰或無關的敏感證件資料。

## Owner 必須決定的事項（內部，不公開）

| 決定 | 發佈前必須完成的結果 |
| --- | --- |
| 公開私隱聯絡渠道 | 選擇品牌／業務用的公開地址或渠道、指定處理人並驗證可收件；不得自動採用或公開 Owner 的個人 Gmail |
| 法定營運者及受眾 | 確認品牌背後實際營運者、所服務的公司／客戶及所在地、是否涉及未成年人；據此核實適用司法管轄區與所需文案，不宣稱已符合 PDPO／GDPR |
| 保存與刪除 | 分別決定訊息／聯絡人、原始 provider 事件、指令稽核、登入資料及備份的保留規則；確認合法保留例外、公司停用／離開後處理及供應商副本範圍 |
| 可執行的申請流程 | 建立身分核實、查閱／更正／刪除申請登記、負責人及回覆程序；先驗證受控清除／去識別化與不可改寫稽核、關聯資料及備份的相容方式，再承諾範圍或期限。現有程式沒有完整申請／刪除操作流程 |
| 供應商與處理地區 | 核實 Meta、Supabase、Vercel 的適用條款、資料處理安排、實際地區及所需披露；不可只憑資料庫地區推斷所有資料均留在同一地區 |

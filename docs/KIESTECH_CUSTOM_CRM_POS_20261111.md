# KiesTECH：獨立客製 CRM 與選配 POS

決定日期：2026-11-11（香港時間）。依據：用戶最新指示；本文件優先於較早文件中將 KiesTECH 推向多公司 SaaS 的建議。

## 產品分工

| 項目 | KiesTECH | 智威特 SmartVolt CRM |
| --- | --- | --- |
| 交付模式 | 每間客戶公司獨立部署、按業務客製及維護 | 同一個獨立 CRM SaaS 供不同公司登入 |
| 人員及品牌 | 同一客戶公司內的員工、品牌、分店及權限 | 各公司工作空間、員工及品牌隔離 |
| 客戶體驗 | 按客戶修改流程、欄位、知識、報告及模組 | 以標準產品及公司設定提供服務 |
| CRM 能力 | 覆客、Customer 360、Flow、AI BOT、推播及成效 | 可參考 KiesTECH 的互動設計及功能模式 |
| POS | 客戶選配內置 POS，或按供應商能力客製接駁 | 正在同一產品內建立 CRM × POS |
| 運行邊界 | 獨立部署、資料儲存、憑證及工作排程；技術選擇按交付確認 | 自有公司身份與 SaaS 工作空間邊界 |

共用經過驗證的程式模式可減少重複維護，但不代表共用客戶資料、登入、金鑰或正在運行的服務。KiesTECH 不依賴 SmartVolt、Growth OS launcher 或其他產品才能使用；亦不因支援多位員工或同公司多品牌而變成 SaaS。

## 可重用的 POS 邊界

保留 CRM 客戶／對話到 POS，以及 POS 預約／套票／訂單返回該客戶對話的入口；切換時保留草稿、購物車與工作上下文。接駁失效時，CRM 覆客、意向、人工跟進仍可獨立使用。

若選內置 POS，先抽離其業務模型和操作規則，再適配 KiesTECH 的員工權限、安裝身份及儲存。不直接依賴 `@/lib/saas/identity`、公司登入、租戶切換、開戶、訂閱或 SmartVolt 的資料庫遷移。正式員工登入、稽核、備份與還原仍須在該客戶安裝中落實。

若接客戶現有 POS，按供應商／版本列出能力：只讀、寫入、即時事件、輪詢、CSV 或只可開啟外部頁面。每項能力獨立驗收，連結入口不等於資料同步，CSV 匯入不等於即時查位。缺少可靠排期資料時，沿用「收集意向 → CS 核實 → 提醒」，BOT 不自行確認有位。

任何接駁須遵守：

| 資料／操作 | 權威來源及約束 |
| --- | --- |
| 客戶配對 | 保存安裝、品牌、連接器及外部會員 ID；電話只作候選配對，多重／不明配對交人工 |
| 預約 | 指定一個權威來源；CRM 意向與確認預約分開，改期／取消使舊提醒失效 |
| 套票 | 由指定 POS 的購買、扣次及沖正事件得出餘額；AI 不推算或自行改寫 |
| 收款／退款 | 金額用整數分；分開訂金、尾數、退款及淨收款，保留單據與交易來源 |
| 更正 | 追加有原因、操作者及時間的沖正事件，不覆蓋或刪除原交易 |
| 同步 | 保存來源時間、接收時間、版本、去重鍵及處理結果；重播不重複記帳，失敗可對帳及重試 |
| 成效 | 回覆、意向、核實 Book、Show、付款及收入分開；來源不足的金額或歸因顯示未知 |
| Flow／BOT | 使用經授權及驗證的資料；接管、通知窗口、同意及退訂規則仍然生效 |

## 交付卡及驗收

| 卡 | 狀態 | 完成條件 |
| --- | --- | --- |
| IDENTITY-01 客戶內部員工權限 | 待正式落實 | 一客一安裝；員工／品牌／分店授權及稽核、復原驗收 |
| POS-01 內置 POS 適配 | 設計已記錄，未移植 | 模型與 SaaS 解耦；排期、收款、套票及 CRM 互跳通過獨立驗收；舊 Demo 資料升級不重設 |
| POS-02 第三方接駁 | 待選供應商及核對能力 | 正式文件、所需權限、測試環境、配對、去重、同步及失敗復原證據 |
| POS-03 交易與資料權威 | 設計已記錄，未啟用 | 獨立交易儲存、角色驗證、重播、退款／扣次沖正及對帳通過；收入定義獲確認 |

先固定客製交付邊界，再按客戶選擇移植內置 POS 或製作供應商 adapter；每個模組保留獨立版本及驗收。現有 CRM、Flow、AI BOT、推播及成效不依賴 POS 才能交付。
